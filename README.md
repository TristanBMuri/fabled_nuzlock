# nuzlock_rl

Nuzlocke gauntlet RL — minimal rebuild (attempt 3). Full plan: `project_overview.md`.

**Rule of this repo: as little code as possible.** Complexity is only added when a
concrete failure demands it. Two prior attempts died of scope bloat.

## Stack

- **Battles**: local Pokémon Showdown server + `poke-env` (Gymnasium-style Python client)
- **RL**: single-file CleanRL-style PPO (PyTorch), TensorBoard for logging
- **Python**: uv, Python 3.14

## Setup

```bash
uv sync                                   # python deps
cd pokemon-showdown && npm install --production   # once, showdown's node deps
uv run python scripts/harvest_teams.py --count 15   # once, team pool
./scripts/setup_custom_formats.sh                    # once, no-gimmicks format

# start servers — one Showdown process per env (node is single-threaded).
# Current scale: 24 ports (8020-8043). ~580MB/worker + ~300MB Showdown each
# (under 1GB/env). 24 envs ≈ 22GB train+sd; needs a clean machine (~45GB free).
# Old project owns 8000-8007 — don't collide.
cd pokemon-showdown
mkdir -p ../logs
for port in $(seq 8020 8043); do
  (node pokemon-showdown start --no-security --port $port > ../logs/showdown_$port.log 2>&1 &)
  # stagger: wait until this port answers before starting the next
  until curl -sf -o /dev/null --max-time 1 http://127.0.0.1:$port/; do sleep 0.3; done
done
```

`--no-security` = no accounts/login needed, bots just connect. The custom
`gen8customgamenogimmicks` format (no Dynamax, no Team Preview — Team Preview
hangs persistent-player challenges) requires the servers to have started
after `setup_custom_formats.sh`.

Only one `train_nuzlocke` / `train` job at a time: parallel envs bind
`port..port+N-1` and a second job will hang on login / crash servers.

## Run

```bash
uv run python scripts/smoke_test.py       # 3 random-vs-random battles, prints state
uv run python scripts/train.py --random   # env sanity: 3 random-policy battles vs heuristic
uv run python scripts/train.py --updates 60   # PPO smoke run (~25 min, ~450 steps/s)

# battler training (one Showdown server per env)
uv run python scripts/train.py --arch attention --envs 4 --updates 500

# nuzlocke meta-policy (gauntlet env; --random = one verbose episode)
uv run python scripts/train_nuzlocke.py --random
uv run python scripts/train_nuzlocke.py --envs 4 --updates 500
# multiprocess rollouts (one process+Showdown port per env). Resumes nuzlocke_latest.pt.
mkdir -p logs
ROLLOUT=1024 uv run python -u scripts/train_nuzlocke.py --envs 24 --updates 400 \
  --seed 1 --port 8020 2>&1 | tee logs/nuzlocke_train.log
```

Checkpoints land in `checkpoints/` after every update (`ppo_latest_<arch>.pt`,
`nuzlocke_latest.pt`). Battles generated by the gauntlet are appended to
`data/teams/gauntlet_harvest/battles.jsonl` (future battler training data).
Train auto-resumes weights from `nuzlocke_latest.pt` when present.
Showdown + train text logs live under `logs/` (gitignored).

## TensorBoard

```bash
uv run tensorboard --logdir runs --port 6006
# then open http://localhost:6006
```

- Every training run writes its own `runs/<timestamp>-<tag>/` directory — the
  tag tells you which (`-attention-pool`, `-mlp-pool`, `-nuzlocke`, `-nuzlockex4`,
  `-nuzlockex12`, `-nuzlockex24`).
- All runs show in one view (left sidebar: toggle runs on/off, color per run).
  Useful scalars: `win_rate_20`, `episode_reward`, `entropy`, `explained_variance`,
  `approx_kl`, `steps_per_sec`; meta-policy runs add `trainers_cleared`;
  pool runs add per-team `win_oppNN`.
- What healthy looks like: entropy decays smoothly (not instantly to 0),
  `explained_variance` trends above 0, `approx_kl` stays small (< ~0.02).
- Without a browser: quick check of the latest run's scalars —

```bash
uv run python -c "
from tensorboard.backend.event_processing.event_accumulator import EventAccumulator
import glob
run = sorted(glob.glob('runs/*'))[-1]
ea = EventAccumulator(run); ea.Reload()
print(run)
for tag in ea.Tags()['scalars']:
    evs = ea.Scalars(tag)
    print(f'{tag:20s} n={len(evs):3d} last={evs[-1].value:+.3f}')
"
```
